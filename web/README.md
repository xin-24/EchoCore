# EchoCore 管理前端

独立 React + TypeScript + Vite 工程。Go 只提供 `/api/admin/v1/`，不嵌入、不读取前端构建产物。

当前实现：管理登录 / 退出、主题、真实素材列表与静态预览、QQ 收藏描述编辑、带版本检查的批准 / 停用、同步请求及状态。运行概览、群控制、事件与用量、配置查看 / 编辑仍待后续里程碑，导航不提供空壳入口。

## 启动

使用 Node 22 LTS（至少 22.12）。在根目录 `config.yaml` 增加：

```yaml
admin:
  enabled: true
  frontend_origin: "http://127.0.0.1:5173"
```

在后端进程环境设置 `ECHOCORE_ADMIN_KEY`，使用自己生成的 32～256 字节随机密钥。可以放入根目录被 Git 忽略的 `.env`，但程序不会自动读取它：启动 Go 前需在当前终端加载。它不是 NapCat Token，也不是 LLM Key。不要把密钥写入 `web/`、`VITE_*` 或 YAML。

```sh
# 终端一：项目根目录；仅加载你信任的 .env
set -a
source .env
set +a
go run ./cmd/server
```

```sh
# 终端二：独立前端
cd web
npm ci
npm run dev
```

打开 `http://127.0.0.1:5173`。不要混用 localhost。8080 必须是 Go 的回环监听端口，5173 冲突时直接失败。密钥缺失或不合要求时管理 API 不启用，但机器人继续运行。

登录后的表情库使用真实服务数据，不含模拟素材。QQ 收藏来源需另行启用并让 NapCat 登录机器人账号。已有缓存可离线审核；同步必须有已确认的在线账号。选择账号后可以查看同步状态并手动请求同步。

- 本地素材只读；清单中禁用的本地条目目前不会加载，因此不会出现在网页中。
- QQ 描述只保存到 EchoCore，不回写 QQ；保存描述不会批准。
- 批准前需要有效、未过期的缓存和描述。批准适用于该机器人所有可回复会话。
- 并发同步 / QQ 命令修改后，旧版本网页提交会返回冲突。
- 卡片使用第一帧 PNG；详情可播放原图 / GIF，不同时播放多张。
- 同步失败当前沿用已有服务的错误分类；更细的逐项下载诊断尚未补全。

## 验证

```sh
npm run typecheck
npm run test -- --run
npm run build
npm run test:e2e
```

浏览器测试使用本机 Chrome，固定 15173 / 18081 测试端口；自动启动隔离 Go 测试服务，临时生成素材和数据库，不读取真实配置、不调用模型、不连接 QQ。测试完成关闭测试服务。不要同时占用这些端口。

`npm run dev` 不是生产部署。`dist/` 后续由独立静态服务与反向代理提供；本阶段不安装系统服务，也不把构建产物加入 Go。
