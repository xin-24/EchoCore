## 2. 验收准备

1. 在原来运行 Go 的终端按 `Ctrl+C`，确认服务退出。
2. 保留该终端已有的模型配置和密钥环境变量，进入项目根目录后执行 `go run ./cmd/server`。不要把密钥粘贴到验收记录或聊天中。
3. 确认启动日志的 Provider 不是 `disabled`，随后出现 `OneBot WebSocket connected`。如未连接，在 NapCat 检查反向 WebSocket 客户端地址 `ws://127.0.0.1:8080/onebot/v11/ws`。
4. 确认 NapCat 中 QQ 已登录。使用另一个 QQ 账号作为测试发送者；机器人自己发的消息会被过滤。
5. 准备测试群 A；测试发送者须在群开关控制白名单中。跨群隔离另需群 B，权限检查另需非白名单成员。
6. 从 QQ 界面选择真实的 @机器人，不要手动输入看起来像 @ 的普通文本。

每项按顺序进行，等上一项回复完成再继续。测试可能产生真实模型调用费用，优先在小测试群中执行。

## 5. 日志判断与问题反馈

- `Router message routed` 中的 `ai_candidate` 只代表进入候选，不等于模型生成或发送成功。
- `LLM generation completed` 代表生成完成；还需检查 `OneBot reply sent` 以及 QQ 实际收到的消息。
- `LLM participation ignored` 表示判断路径未继续生成。当前该条日志未区分有效 `ignore` 与无效模型输出，单凭它不能证明语义判断成功；证据不足时标记待确认。
- `LLM request failed` 或发送失败不能记为成功的选择性忽略。
- 群关闭后仍可能打印原始收消息日志，不代表触发 AI。
- 不要公开完整 DEBUG 日志，其中可能包含聊天正文。反馈时优先提供测试编号、时间、QQ 现象和脱敏后的关键状态行。
